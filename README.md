# OpenCode-HyperDCP

**OpenCode-HyperDCP** is a context management plugin for the [OpenCode](https://opencode.ai) AI coding agent. Forked from [opencode-dynamic-context-pruning](https://github.com/Opencode-DCP/opencode-dynamic-context-pruning), it gives you an **observable and controllable** context environment optimized for model stability and cost efficiency.

One npm package supports **OpenCode v1 and v2**, with native server and TUI registrations sharing the same DCP operations and persisted state. See [CHANGELOG.md](CHANGELOG.md) for release details.

[Installation](#installation) - [Quick Start](#quick-start-make-and-inspect-your-first-block) - [Features](#feature-tour) - [References](#reference)

## Philosophy

An AI agent's context window should be **100% observable and 100% controllable**. HyperDCP treats every compression as a _visible block_:

- **Observable** — inspect exactly what was compressed, what survived, and how much was saved. See what is generated by summerization.
- **Controllable** — rewrite a summary, switch versions, protect a message, or cull a block entirely.
- **Lossless-in-practice** — almost nothing is forgotten or overwritten. It is possible to undo the compression, or undo the summary revision.

## How HyperDCP manages context

### Message compression and recall

The agent summarizes a completed range of conversation. In subsequent context, that summary occupies the place of the original messages. Unlike default compaction, only selected ranges are compressed at chosen times; messages outside compressed ranges remain untouched.

The agent can retrieve individual original messages by calling `recall_compressed` when later discussion involves details of prior arguments, debug output, or earlier evidence.

### Observable summary blocks (DCP blocks)

Summarized ranges become **DCP blocks** — each with its own topic, message boundaries, token accounting, and version history. Blocks are not compressed again by default, so the context may contain multiple summaries replacing different ranges.

The **DCP Blocks** sidebar lists each block's range, active version, and token cost, with a header showing total raw tokens saved. Open the **DCP TUI Blocks** menu to inspect content, rewrite the summary with **e**, switch versions with `/dcp toggle`, decompress to restore original messages with `/dcp decompress`, or cull a block with `/dcp toggle` (which sets version `v0`).

![DCP block list](docs/screenshots/dcp-blocks-list.png)

Open a block to read its summary with per-version tabs; the active version is marked `*` (here `[*v2]`). Switching tabs is view-only and does not change which version is live. Long summaries scroll with the mouse wheel or **Up/Down**, **Page Up/Page Down**, **Home/End**.

![Block detail with version tabs](docs/screenshots/dcp-block-detail.png)

The **DCP Messages** view (`/dcp-tui-messages`) lets you browse underlying messages and their compression state page by page. Views refresh incrementally after assistant completion without losing your place.

### Memo — durable project memory

The **memo** is a per-session document that survives compaction. The agent keeps working commands, user constraints, and procedural knowledge there, so the most active facts does not get stale or burried in middle of the context. Agents are instructed to maintain this document when they once get into the context maintainance mode.

### Skills

The native `skill` tool loads skills through OpenCode. A successful load marks the skill loaded; `unload_skill` removes it. The protected list is separate: only a successful `leave_housekeeping` copies the loaded list into it, and protected skill calls and results are injected immediately after the memo, or at the same context anchor when there is no memo. Open **DCP Skills** (`/dcp-tui-skills`) to inspect the current session's loaded list and which skills are being injected as protected context.

### When does context get summarized?

The agent writes summaries and calls compression tools. HyperDCP supplies guidance and nudges as context grows; a nudge is not itself a compression operation.

By default, the agent can request compression without a manual trigger, subject to OpenCode permissions. To require an explicit trigger, use `/dcp manual on`, then `/dcp compress` when you want a maintenance pass. Manual mode can also be set in configuration.

**Autotoggle** is a separate control. `/dcp autotoggle on` allows the agent to switch an existing block's summary version, including version `0` (cull). It is not a prerequisite for creating a block, and you do not need it to switch versions yourself with `/dcp toggle`.

### Housekeeping transactions

The agent's context-maintenance edits are transactional. Agents are allowed to call context modifying tools only in housekeeping mode. Compression, memo edits, expansions, and summary changes accumulate in a draft.

Primary purpose of this transactional mechanism is protect cached tokens, where model requests are required to share exactly equal preceding history events to utilize cache read (prefix-based KV caching).

Ordinary tools are blocked during housekeeping by default. (configurable via [`housekeeping.allowedTools`](docs/context-reference.md#configuration); OpenCode permissions still apply).

The agent has the same controls you do in the housekeeping mode, so context management can happen mid-task without breaking the observable model:

- `recall_compressed` — search and retrieve the original messages folded into any block.
- `rewrite_summary`, `edit_summary`, `append_summary`, `fetch_summary_versions` — read and revise a block's summary as new versions.
- `expand_block` — extend a block's range to absorb newly uncovered messages.
- `edit_memo` / `read_memo` — maintain durable project memory outside the volatile chat history.

## Installation

Install from official npm respository:

OpenCode v1:
    ```sh
    opencode plugin @architectural-composition/opencode-hyperdcp
    ```
In an active session, open the command palette (`ctrl+p`) and look for **DCP Blocks**, **DCP Messages**, **DCP Memo**, and **DCP Skills**. These pages confirm the TUI plugin is registered; `/dcp` provides the server command entry point.

HyperDCP's own settings belong in a separate [`dcp.jsonc` file](docs/context-reference.md#configuration).

## Quick start: make and inspect your first block

Use an installed OpenCode session with a completed investigation or other finished conversation worth summarizing.

1. Use context by reading some files (The default rejects ranges smaller than 2,000 tokens.)
```txt
Read /path/to/file1 and /path/to/file2
```

```txt
→ Read /path/to/file1
→ Read /path/to/file2
```

2. Request a compression pass:

   ```text
   compress; keep the summary of read files
   ```

    The command invokes the agent, which enters housekeeping, selects completed ranges, writes summaries, and commits the maintenance pass. Wait for it to finish. If there is no eligible completed range of sufficient size, continue reading to increase context usage.

3. Open **DCP Blocks** from the command palette (`/dcp-tui-blocks`). You will see a block created by the pass. Click the entry to read its summary.

4. Press **e** to open the block's active summary in your text editor (`$VISUAL`, then `$EDITOR`, then `vi`). Add a line and save and exit. The saved text becomes a new active version.

5. You will see the two versions of summaries. Click the tab to compare older and current version. The `*` marker denotes the active version. Press **Esc** to return.

6. Ask the agent to recall the precise wording of the former prompt and see if the agent calls `recall_compressed` to retrieve older messages.

## Feature tour

### Block list — see every compressed range at a glance

The sidebar lists each block with its range, mode, active version, token cost, and topic. A summary header shows the running total of raw tokens saved.

![DCP block list](docs/screenshots/dcp-blocks-list.png)

### Block detail — per-version tabs

Open a block to read its summary. Every block keeps multiple versions; tabs mark the currently active one with `*` (here `[*v2]`). Switching tabs is view-only — it does not change which version is live.

Long summaries scroll with the mouse wheel or **Up/Down**, **Page Up/Page Down**, and **Home/End**. The header, version tabs, and Edit control stay visible. Block summaries and memo documents render Markdown with colored headings.

![Block detail with version tabs](docs/screenshots/dcp-block-detail.png)

### Culling — deliberately forget a range

A block can be set to version `v0`, which hides its summary while still pruning the covered messages. The detail page shows `(disabled)`, and the block reads `31.2K→0 tok`. This is how you intentionally drop context you no longer need.

![A culled block](docs/screenshots/dcp-block-culled.png)

### Edit summaries in `$EDITOR`

Click **Edit (e)** or press **e** on a block to hand the summary to your `$EDITOR` through a header-delimited temp file; save and quit to apply it as a new active version. The editable document excludes the `[Compressed conversation section]` header and trailing block-reference tag. Summary tools use the same document-only representation; DCP supplies those wrappers separately in model context. The sidebar list can also be collapsed to reclaim screen space.

![Editing a block summary in $EDITOR](docs/screenshots/dcp-block-edit-key.png)

### Messages view — inspect the tracked chain

Browse the underlying messages and their compression state, page by page. Use **<** for Newer and **>** for Older, or click the paging buttons. Conversation changes refresh after the assistant finishes, without jumping away from a valid current page.

![DCP messages view](docs/screenshots/dcp-messages.png)

### Memo — durable, editable project memory

A per-session memo that survives compaction and can be edited with **Edit (e)**, keeping working commands, constraints, and takeaways out of the volatile chat history.

![DCP memo view](docs/screenshots/dcp-memo.png)

### Skills — immediate loading, stable protected context

The native `skill` tool still loads skills through OpenCode. A successful load immediately marks the skill loaded; loading it again fails unless `force: true` is supplied. A failed load leaves it unloaded, including a failed forced reload. `unload_skill` removes a skill from the loaded list. Both tools are allowed during housekeeping, subject to OpenCode permissions, and entry guidance lists the loaded skills.

The protected list is separate: only a successful `leave_housekeeping` copies the loaded list into it. Protected skill calls and results are injected immediately after the memo, or at the same context anchor when there is no memo. Loading or unloading during housekeeping does not change that injected prefix until leave succeeds. Reverting housekeeping restores its protected list without rolling back immediate loaded status. Skill management alone does not satisfy the leave guard.

Open **DCP Skills** (`/dcp-tui-skills`) to inspect the current session's loaded list. Each row shows its name/title and status: **in context** means loaded but not protected; **injected** means loaded and protected. The list updates when loaded or protected state changes, without waiting for housekeeping leave to reflect a load or unload. It is read-only and does not list the host's entire skill inventory.

Skills are not blanket-protected by default. Unloading stops the protected injection after the next successful leave; original skill messages remain in history and can be compressed normally. Explicit `protectedTools` configuration is still respected. Existing sessions start with both lists empty rather than inferring loads from old tool calls. Skill lifecycle tracking uses each host's native tool interfaces.

### Refresh — committed state without losing your place

The sidebar and pages share a session-scoped cache. Conversation updates are fetched incrementally after assistant completion, rather than reloading the entire conversation on every event. Block, memo, and skill views observe persisted state; draft block and memo edits remain private until housekeeping commits. Editor saves use the same refresh path. Valid page, block, and explicit summary-version selections are preserved as data changes.

## Usage

1. Open the DCP pages from the command palette (`ctrl+p`) with `/dcp-tui-blocks`,
   `/dcp-tui-messages`, `/dcp-tui-memo`, or `/dcp-tui-skills`. Use **Esc** to go back.
2. When context grows, act on the nudge:
    - review blocks in the **DCP Blocks** sidebar,
    - rewrite or switch a summary version,
    - protect messages you must keep, or cull blocks you no longer need.

The plugin ships alongside server-side commands (`/dcp ...`) and AI tools (search & retrieve of compressed messages) for finer-grained control.

On v2, informational command output and message-style compression notifications are queued without waking the agent just to display them; immediate transcript display is not guaranteed. `/dcp compress` and `/dcp rewrite` deliberately invoke the agent. Toast notifications use the TUI connection.

For example, to allow a specific read-only tool during housekeeping, add this to the DCP configuration:

```json
{
    "housekeeping": {
        "allowedTools": ["read"]
    }
}
```

Compression protection is configured separately from command protection:

```json
{
    "compress": {
        "protectSubagent": "metadata",
        "protectedTools": ["read"]
    }
}
```

`compress.protectSubagent` accepts `none`, `metadata`, or `full` and defaults to `metadata`. `compress.protectedTools` protects configured tool outputs during compression; `task` and `subagent` outputs are not appended through this generic list.

- `none` leaves subagent messages subject to ordinary compression.
- `metadata` retains every running execution, plus terminal executions whose termination message is covered by the last summary block projected in conversation order. Records appear after protected skills and include the calling reference, child session, status, title, steering references, and a result reference for completed executions.
- `full` also retains that execution's delivered report, without fetching a later answer from the child session.

Steering a running child adds to its execution entry; resuming after termination creates a separate entry. Canceled and failed executions follow the same coverage rule as completed executions, but omit the result reference. Command protection defaults are independent of these settings.

## Configuration

DCP settings live in `dcp.jsonc`. For example, to allow a specific read-only tool during housekeeping:

```json
{
    "housekeeping": {
        "allowedTools": ["read"]
    }
}
```

Compression protection is configured separately:

```json
{
    "compress": {
        "protectSubagent": "metadata",
        "protectedTools": ["read"]
    }
}
```

- `compress.protectSubagent` accepts `none`, `metadata` (default), or `full`.
  - `none` leaves subagent messages subject to ordinary compression.
  - `metadata` retains every running execution, plus terminal executions whose termination message is covered by the last summary block projected in conversation order, with calling reference, child session, status, title, steering references, and result reference.
  - `full` also retains that execution's delivered report, without fetching a later answer from the child session.
- `compress.protectedTools` protects configured tool outputs during compression. `task` and `subagent` outputs are not appended through this generic list.

See the [configuration reference](docs/context-reference.md#configuration) for all options.

## Notes

- On OpenCode v1, manual block edits, memo edits, and summary-version toggles trigger a user message. On v2, server-side informational command (such as /dcp stats) output and message-style compression notifications may be queued rather than appearing immediately in the transcript. `/dcp compress` and `/dcp rewrite` deliberately invoke the agent. See [host behavior and known issues](docs/context-reference.md#host-behavior-and-known-issues).
- Screenshots are generated by the PTY-driven capture harness in `scripts/` (see `scripts/README.md`).
